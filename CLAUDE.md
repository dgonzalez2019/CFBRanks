# Project notes for Claude Code

Static site + Python tooling for college football power rankings. Teams are ranked by score = power rating + 0.5 × résumé points; strength of record (SOR) is shown on team pages as a reference.

- **Single page:** `index.html` holds all HTML, CSS and JS. No framework, no build. Keep it that way unless asked.
- **Data contract:** `data/games.json` = `{season, updated (ISO UTC), games: [[week, home, away, home_pts, away_pts, neutral 0/1, home_fbs 0/1, away_fbs 0/1], ...]}`. Postseason weeks are offset by +20. Optional 9th element = box score `[home pass yds, home pass att, home rush yds, home rush att, away same four]` (net passing yards; attempts from completionAttempts). `fetch_games.py` keeps stored box scores and only requests `/games/teams` for weeks missing some, to stay inside the free API tier.
- **Algorithm (keep JS `compute()` and Python `compute()` in sync):**
  1. Ridge least squares on tanh-compressed margins (cap 21, ridge 2) with an estimated home-field term; neutral sites get 0; all non-FBS teams pooled as "FCS (pooled)"; ratings centered on the FBS mean.
  2. Outcome SD calibrated from residuals ×1.05; win prob = normal CDF.
  3. For each game, P(benchmark team wins at that venue); benchmark = Nth-rated team (default 25).
  4. WAB = wins − Σ benchmark win prob (SOR rank key); SOR% = Poisson-binomial P(benchmark ≥ actual wins). SOR is a reference, not the main ranking.
  5. Win value = 1 − p; loss cost = p. Quadrants by opponent's power rank, any venue: Q1 ≤25, Q2 ≤50, Q3 ≤80, else Q4 (incl. FCS). Deliberately power rank, not overall rank: using overall rank creates a feedback loop that inflates whole conferences.
  6. Résumé points per game by quadrant: wins 4/2/1/0.5 (Q1–Q4), losses cost 0.85 × 0.5/1/2/4. Ranking score = rating + 0.5 × résumé (constants WIN_PTS, LOSS_PTS, LOSS_WEIGHT, RESUME_WEIGHT in both files).
- **Results only tab:** separate Colley Matrix ranking (`colley()` in both files): W/L only, no margins or venue; C = 2I + games played − head-to-head counts, b = 1 + (W − L)/2. Ties skipped.
- **Matchup tab:** separate predictor (`predictor()`/`predict()` in JS, `fit_predictor()`/`predict()` in Python): ridge 1 on point margins capped at 35 + HFA for the margin; ridge 2 offense/defense points model for the total; win prob = normal CDF with SD = in-sample RMSE × 1.4 (out-of-sample residual SD was ~1.4× in-sample). JS `backtest()` reports week-by-week out-of-sample accuracy in the tab's note. Passing/rushing efficiency (`efficiency()`/`adjOD()` in JS, `efficiency()`/`adj_od()` in Python): attempt-weighted ridge (50) on yds/pass att and yds/carry = league avg + offense + opposing defense (+ home), points = c0 + c1·YPA + c2·YPC regressed on this season's game sides; efficiency margin gets EFF_WEIGHT 0.25 of the final margin (chosen by backtest: 66.2% / 12.26 MAE vs 64.9% / 12.41 without; raw yards per game made it worse). Needs ≥50 games with box scores, else skipped. CLI: `--json data/games.json --predict TEAM1 TEAM2 [--venue neutral|team1|team2]` (CSV has no box scores).
- **Lines tab:** `data/lines.json` = `{season, updated, games: [[week, home, away, neutral, home spread (median, negative = home favored), total, home_pts|null, away_pts|null, start, [books]]]}` from `fetch_games.py --lines`. `renderLines()` compares `predict()` with −spread for upcoming games and uses `backtest().preds` (week-by-week, earlier games only) for the track record.
- **Player values:** `data/players.json` = `{season, updated, players: [[team, name, position, countable plays, avg PPA per play]]}` from `fetch_games.py --players` (`/ppa/players/season`, garbage time excluded; offense only).
- **Updates:** GitHub Action `update-games.yml` runs `scripts/fetch_games.py` with secret `CFBD_API_KEY` and commits `data/games.json`.
- **Test:** `python -m http.server` and open the page; `python scripts/cfb_sor.py --csv <file>` for a CLI check.
