# Project notes for Claude Code

Static site + Python tooling for college football power rankings. Teams are ranked by score = power rating (the Matchup model's) + 1.0 × résumé points; strength of record (SOR) is shown on team pages as a reference.

- **Single page:** `index.html` holds all HTML, CSS and JS. No framework, no build. Keep it that way unless asked. Look: "night game" theme (dark default, day toggle stored as `sor.theme`): fixed `.stage` background (floodlights, perspective turf, grain), glass panels, podium hero + stat strip + ticker (`renderHero()`), team badges (`mono()`: the team's logo from `data/teams.json` = `{v: 2, updated, teams: [[school, logo, dark-background logo|null, color, alt color]]}` written weekly by `fetch_games.py --teams` from `/teams`, light/dark version by theme; initials on a name-hashed hue when missing or the image fails), count-ups via `data-count` (a MutationObserver on `main` also staggers table rows with `--i`), sliding nav indicator (`moveInd()`), scroll reveals with CSS `animation-timeline: view()`; all motion off under prefers-reduced-motion.
- **Data contract:** `data/games.json` = `{season, updated (ISO UTC), games: [[week, home, away, home_pts, away_pts, neutral 0/1, home_fbs 0/1, away_fbs 0/1], ...]}`. Postseason weeks are offset by +20. Optional 9th element = box score `[home pass yds, home pass att, home rush yds, home rush att, away same four]` (net passing yards; attempts from completionAttempts). Optional 10th element = matchup stats `[home sacks made, TFL made, QB hurries made, turnovers committed, 3rd-down conversions, 3rd-down attempts, away same six]` (zero counting stats are omitted by the API, stored as 0). `fetch_games.py` keeps stored box scores and only requests `/games/teams` for weeks missing some, to stay inside the free API tier.
- **Algorithm (keep JS `compute()` and Python `compute()` in sync):**
  1. Power rating = the Matchup tab's model (`predictor()`/`fit_predictor()`, with last season's prior and efficiency, see Matchup tab below): each team's neutral-field predicted margin vs one reference team, recentered on the FBS mean (= margin vs an average FBS team; neutral margins are linear in the ratings). `compute(games, bench, prior)` in both files; JS reuses `RESULT.M` as `PRED`; CLI `--prev` seeds it. All non-FBS teams pooled as "FCS (pooled)".
  2. Outcome SD = the Matchup model's SD (in-sample RMSE × 1.4); win prob = normal CDF; HFA = its home term.
  3. For each game, P(benchmark team wins at that venue); benchmark = Nth-rated team (default 25).
  4. WAB = wins − Σ benchmark win prob (SOR rank key); SOR% = Poisson-binomial P(benchmark ≥ actual wins). SOR is a reference, not the main ranking.
  5. Win value = 1 − p; loss cost = p. Quadrants by opponent's power rank, any venue: Q1 ≤25, Q2 ≤50, Q3 ≤80, else Q4 (incl. FCS). Deliberately power rank, not overall rank: using overall rank creates a feedback loop that inflates whole conferences.
  6. Résumé points per game by quadrant: wins 4/2/1/0.5 (Q1–Q4), losses cost 0.85 × 0.5/1/2/4. Ranking score = rating + 1.0 × résumé (RESUME_WEIGHT 1.0 since these ratings are ~2× as spread out as the old tanh-compressed ones, SD 10.4 vs 5.2, keeping the same balance; constants WIN_PTS, LOSS_PTS, LOSS_WEIGHT, RESUME_WEIGHT in both files).
- **Results only tab:** separate Colley Matrix ranking (`colley()` in both files): W/L only, no margins or venue; C = 2I + games played − head-to-head counts, b = 1 + (W − L)/2. Ties skipped.
- **Matchup tab:** predictor, also the power rating behind the rankings (`predictor()`/`predict()` in JS, `fit_predictor()`/`predict()` in Python): ridge 1 on point margins capped at 35 + HFA for the margin; ridge 2 offense/defense points model for the total; win prob = normal CDF with SD = in-sample RMSE × 1.4 (out-of-sample residual SD was ~1.4× in-sample). With last season (`data/history/<season-1>.json`, loaded by the page; `--prev` in the CLI) the margin model starts from `seasonPrior()`/`season_prior()`: last season's margin ratings (cap 45) × PRIOR_KEEP 0.9, new FBS teams at the FCS level, and this season's fit uses cap 45 with ridge 2 toward those priors (tuned on 2022–25: wk1–4 73.4%/13.56 MAE vs 67.9%/15.02 without; wk5+ 70.8%/12.45 vs 69.9%/12.67). JS `backtest()` reports week-by-week out-of-sample accuracy in the tab's note, from week 2 with a prior, else week 5. Passing/rushing efficiency (`efficiency()`/`adjOD()` in JS, `efficiency()`/`adj_od()` in Python): attempt-weighted ridge (50) on yds/pass att and yds/carry = league avg + offense + opposing defense (+ home), points = c0 + c1·YPA + c2·YPC regressed on this season's game sides; efficiency margin gets EFF_WEIGHT 0.25 of the final margin (chosen by backtest: 66.2% / 12.26 MAE vs 64.9% / 12.41 without; raw yards per game made it worse). Needs ≥50 games with box scores, else skipped. CLI: `--json data/games.json --predict TEAM1 TEAM2 [--venue neutral|team1|team2]` (CSV has no box scores).
- **Positional matchups:** `unitRates()` (JS) / `units()` (research) rate sacks and hurries per dropback, TFL and turnovers per play, third-down %, plus YPA/YPC, each fit with `adjOD` (ridge 50). Shown on the Matchup tab only: adding them to the prediction didn't help on held-out 2022–25 (MAE 12.58 vs 12.56 for YPA/YPC only; `research/matchups.py` + `matchups_eval.py`). Points per unit rate were stable across seasons (turnover rate ≈ −110, sack rate ≈ −20, third-down rate ≈ +20).
- **Lines tab:** `data/lines.json` = `{season, updated, games: [[week, home, away, neutral, home spread (median, negative = home favored), total, home_pts|null, away_pts|null, start, [books], median opening spread|null]]}` from `fetch_games.py --lines`. `renderLines()` compares `predict()` with −spread for upcoming games and uses `backtest().preds` (week-by-week, earlier games only) for the track record.
- **Player values:** `data/players.json` = `{season, updated, players: [[team, name, position, countable plays, avg PPA per play]]}` from `fetch_games.py --players` (`/ppa/players/season`, garbage time excluded; offense only). The API omits countablePlays, so plays = totalPPA.all / averagePPA.all. Injury picker (`playerValues()` JS / `player_values()` Python): value = max(0, shrunk PPA − replacement PPA) × plays per game × share: QBs INJ_SHARE_QB 1.25 (fitted on first games a main QB missed: 1.33 ± 0.20 on 2022–25 with the season's starter; 1.29 ± 0.19 on 2022–26 with the starter named from earlier games only), others INJ_SHARE 0.5 (passer and receiver share credit; untested); PPA shrunk toward position average by 50 plays; a team's top player at a position is replaced by its own #2 (shrunk toward league backup level), others by the backup level. `predict(..., outA, outB)` subtracts lost points from margin and total. CLI: `--players data/players.json --out-players "Name, Name"`.
- **Betting market:** over 2022–25 the closing line beat our model every season (winners 72.6% vs 71.1%, avg miss ~12.0 vs ~12.7); the best blend weight on the line was 1.0 in every held-out season and our side of the line covered ~50%. Spread and over/under pick models (`research/picks_*.py`, trained 2022–24, tested once on 2025–26) hit 48% and 51%, and their most confident 10% hit 47% and 45%, so no confidence rating is shown. The QB-out betting rule with the starter named pre-game went 53/51/52/62% in 2022–25 and 46% in 2026 (`research/qb_rule.py`): no edge. Play-efficiency ratings (PPA per play, opponent-adjusted, talent-seeded; `research/ppa_*.py`) didn't help either: edge 3+ vs opening lines 51.6% vs 51.1% for the score model, held-out 2022–25. So the Matchup tab leads with the line when one exists (MKT_SD 15.2, calibrated), adjusted only for players marked out. `research/` holds the scripts; `research/summary.py` writes `data/research.json`, shown on the Lines tab. Past lines/passers/player values: `data/history/<year>_{lines,qb,players}.json` from `scripts/fetch_extras.py`.
- **Injury reports:** `scripts/fetch_injuries.py` (SportsDataIO `/v3/cfb/scores/json/InjuredPlayers` + `Teams`, secret `SPORTSDATAIO_API_KEY`) writes `data/injuries.json` = `{updated, source, injuries: [[team (our names), player, pos, status, body part, start date, updated, note]]}`; teams mapped by name with `ALIASES`. The page auto-marks status Out in the injury picker (`outSet()`); our model scales a listed player's value by `shareBefore()` (share of his team's games dated before his injury start, dates from lines.json), while the betting-line box only moves for the viewer's changes to the report (`lineOut()`), since public reports are priced in. No injury history exists, so this can't be backtested.
- **Live tracker:** `scripts/track_picks.py` (last step of the update workflow, after injuries) saves our Matchup-model margin (last-season prior, efficiency, `injury_adjustments()` for players listed Out — identical to the page's `autoModelOut()`) for games kicking off within 7 days into `data/tracker.json`, with the current and opening lines; records freeze at kickoff and are graded after the final for fixed strategies: `model_close` (our side of the last pre-kickoff line), `model_open` (our side of the opening line), `fav37` (favorite at 3 or 7 ±0.5). The Lines tab shows each strategy's live record by edge size. Confidence (`conf` in tracker.json): logistic probability our pick covers, `confidence()` in track_picks.py with `CONF_COEF` from `research/conf_score.py` (2022–25 fit) on bad = −(pick last-game cover − opponent's)/14 (no line = 0), dis = −side·(`ppa_margin()` − line)/7, gap = |ours − line|/7, both = bad>0 & dis>0. Each week's top 10% by conf = `top_conf` (Top confidence), top 5% = `top5`; flags freeze at kickoff. Held-out top 10%: 178–148 (54.6%) over 2022–26; scores span ~48–56% and 54–56% scored games covered 55% in 2025–26. Shown per game as a % badge (top right of the Matchup box and each Lines card) and as live-record rows. Totals confidence (`tconf`, `total_confidence()` with `TCONF_COEF` from `research/conf_total.py`, 2022–25 fit): probability our side of the total wins (s = +1 over) on gap = |our total − line|/7, last = −s·(both teams' last-game total − its line)/14, form = −s·(both teams' shrunk season over rates − 1), pace = s·(avg plays/game − 67.2)/10, high = −s·(line − 55)/10; weekly top 10%/5% = `ttop_conf`/`ttop5`; graded as `ou_model`, `ou_top`, `ou_top5`. Held out top 10%: 169–138 (55.0%) but 47/47/72/59/44% by season (2022–26), so the page warns it's unsteady. Top picks (`renderPicks()`, first option of the Lines tab's switch and its default; old `#picks` links open it) is a pre-game summary of the Lines tab's Spreads and Totals views: this week's tracked picks with conf/tconf ≥ 50% for games not yet kicked off, most confident first, All / Spreads / Totals filter, the side to take as each card's headline. Its ★ Top 5% / Top 10% marks rank all of the week's upcoming scored picks together (spreads and totals in one list), unlike the per-market `top_conf`/`ttop_conf` flags used under Spreads and Totals. The Lines tab switch is Top picks | Spreads | Totals (`LMODE`, stored as `sor.lmode`, `lineSeg()`); all three views use the same row cards (`pickCard()`, `gameLine()` with logos), dates in ET via `gameWhen()`. `data/ppa.json` = this season's per-game team PPA from `fetch_games.py --ppa`. No betting: this is the model's out-of-sample record.
- **Updates:** GitHub Action `update-games.yml` runs `scripts/fetch_games.py` with secret `CFBD_API_KEY` and commits `data/games.json`.
- **Test:** `python -m http.server` and open the page; `python scripts/cfb_sor.py --csv <file>` for a CLI check.
